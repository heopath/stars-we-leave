# 우리가 남긴 별 · v0.2.1

우연히 만나고, 선택하며 살아가고, 하나의 별이 되어 다음 세대에 이어지는 한국어 브라우저 게임 시제품입니다.

- 플레이 진입점: [게임 실행 파일](./docs/index.html)
- 다운로드: [v0.2.1 ZIP](./downloads/stars-we-leave-v0.2.1.zip?raw=true)
- 간편 실행: [독립 HTML](./우리가-남긴-별-v0.2.1.html?raw=true)

위 링크는 저장소 내부의 상대 경로입니다. GitHub에서 HTML을 클릭하면 코드가 표시될 수 있습니다. 온라인 플레이 주소는 아래 GitHub Pages 설정을 마친 뒤 Settings → Pages에 표시되는 주소를 사용하세요. 이 README는 배포가 완료되었다고 가정하지 않습니다.

## 게임에 들어 있는 것

- 8, 16, 24, 33, 42, 53, 64, 75, 84살의 아홉 순간과 각 세 가지 선택.
- 클릭·터치·방향키·WASD로 빛에 다가가기, 선택 전 다른 길 살펴보기, 선택 후 기억 읽기.
- 이전의 연습·연락·거주지가 우연한 공연과 재회에 미치는 영향. 우연의 시드는 저장되어 새로고침해도 유지됩니다.
- 아홉 기억의 별자리 엔딩과 PNG 내보내기 기능.
- 악보·편지·씨앗·수첩의 계승, 실제로 플레이하는 다음 세대, 이전 세대의 기억장.
- 브라우저 자동 저장, 일시정지, 기본 꺼짐인 자체 화음.

다음 세대는 새 이름과 우연을 받지만 같은 아홉 나이의 이야기 틀을 사용합니다. 시대별로 완전히 다른 이야기가 생성되는 게임은 아닙니다. 첫 버전의 저장이 있는 브라우저에서는 보존된 첫 이야기로 이어갈 수 있습니다.

## v0.2.1에서 고친 점

- 손주가 물건을 직접 건네받았는데도 조상을 만나지 못한 사람으로 표현하던 기억 문장을 수정했습니다.
- 읽을 수 없는 저장이 있을 때, 새 삶을 시작하기 전에 확인을 받습니다. 원문을 파일로 내려받거나, 같은 브라우저의 별도 백업에 보관·검증한 뒤 시작할 수 있습니다.
- 백업에 실패하거나 확인 중 다른 창에서 저장이 바뀌면 새로 시작하지 않습니다.
- 저장을 읽을 수 없는 환경에서는 기존 기록을 덮어쓰지 않고 현재 창에서만 플레이합니다.
- 시작·확인 버튼을 연속으로 눌러 생애가 중복 생성되는 문제를 막았습니다.

아홉 단계의 이야기, 선택 구조, 우연의 확률, 디자인은 그대로입니다.

## 실행하기

### 다운로드해서 열기

ZIP을 풀고 `stars-we-leave/우리가-남긴-별-v0.2.1.html`을 브라우저로 엽니다. 필요한 화면·이야기·스타일이 한 파일에 들어 있습니다. 파일 직접 실행과 저장 방식은 브라우저에 따라 다를 수 있습니다. 실제 `file://` 실행은 이번 검증에 포함되지 않았습니다.

다운로드 ZIP은 기존 v0.2.1 전달본 그대로입니다. 이 저장소에 추가한 GitHub Pages 구성·검사 스크립트는 들어 있지 않습니다. 저장소 전체가 필요하면 GitHub의 Code → Download ZIP을 사용하세요.

### 로컬 서버로 열기

Node.js 22 이상이 필요합니다. 외부 패키지 설치는 필요하지 않습니다.

```sh
npm start
```

브라우저에서 `http://127.0.0.1:4319/`로 접속합니다. 서버는 `dist/`를 제공합니다. 게임 소스도 빌드 도구 없이 읽고 수정할 수 있는 HTML, CSS, JavaScript 모듈입니다.

### GitHub Pages로 게시하기

1. 이 저장소의 파일을 `main` 브랜치에 올립니다.
2. Settings → Pages → Build and deployment에서 Source를 **Deploy from a branch**로 선택합니다.
3. 브랜치는 **main**, 폴더는 **/docs**를 선택하고 Save를 누릅니다.
4. 배포가 완료되면 같은 화면에 표시되는 주소로 접속합니다. 실제 페이지와 게임 시작을 확인한 뒤 주소를 공유하세요.

`docs/`에는 실행 파일이 이미 준비되어 있습니다. GitHub에서 별도 Node.js 빌드를 할 필요는 없습니다. `docs/.nojekyll`도 포함되어 있습니다. 설정 방법은 [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 참고하세요.

게임을 고친 뒤에는 다음 명령으로 독립 HTML과 `docs/`를 다시 만듭니다. 이 명령은 로컬 파일만 준비하며 업로드나 배포를 하지 않습니다.

```sh
npm run build
npm test
npm run check
```

`dist/`를 원본으로 수정하고, 생성된 `docs/`와 독립 HTML도 함께 커밋해야 Pages에 반영됩니다. `docs/`만 직접 수정하면 다음 빌드에서 덮어씁니다. 다운로드 폴더의 ZIP은 보존된 v0.2.1 배포본이므로 빌드할 때 자동으로 변경하지 않습니다.

## 저장과 복구

- 진행은 사용한 브라우저의 localStorage에 저장됩니다. 서버 저장이나 클라우드 동기화가 아닙니다.
- 다른 사이트, 다른 브라우저, 독립 HTML로 기존 저장이 자동 이동하지 않습니다.
- 현재 저장 키는 `stars-we-leave:lineage:v2`입니다. 읽을 수 없는 기록의 백업 키는 `stars-we-leave:lineage:v2:unreadable-backup:`으로 시작합니다.
- 백업은 원래 문자열을 그대로 저장하며 기존 백업을 덮어쓰지 않습니다. 브라우저 데이터를 지우면 이 백업도 사라질 수 있습니다.
- “이전 기록 파일 내려받기”는 원문을 텍스트 파일로 다운로드합니다. 다운로드 시작 안내가 실제 저장 완료를 보장하지 않으므로 파일이 있는지 확인하세요. 파일을 게임에 다시 불러오는 기능은 제공하지 않습니다.
- 백업 실패 시 원래 기록을 바꾸지 않습니다. 저장 공간·브라우저 설정을 확인한 뒤 다시 시도할 수 있습니다.
- 브라우저가 저장 읽기를 막으면 현재 창에서만 플레이합니다. 새로고침하거나 창을 닫으면 이번 진행이 사라집니다.
- 정상 기록에서 새 삶을 시작하면 확인 후 현재 진행과 가족 기록이 바뀝니다. 여러 창의 진행을 병합하지 않으므로 한 창에서 플레이하는 편이 좋습니다.

## 검사 결과와 한계 · 2026-10-20

Node.js v24.19.0에서 `npm test` 28개가 통과했습니다. 첫 버전 이야기 6개, 현재 이야기 11개, 저장·시작 UI 회귀검사 11개입니다.

- 한 시드에서 가능한 19,683개 선택 경로와 첫 버전의 729개 경로.
- 여러 시드의 우연, 연습·연락의 영향, 네 가지 계승, 3대 기록 보존, 잘못된 선택·저장.
- 손주 기억의 일관성, 깨진 저장의 확인·취소·원문 보관, 백업 실패, 중복 클릭, 저장 권한 오류.
- `npm run build`로 독립 HTML과 Pages 파일 재생성.
- `npm run check`로 `dist/`와 `docs/`의 일치, 상대 경로·자산 존재, 독립 HTML 일치, ZIP 존재, 모든 `.mjs` 구문 검사.

UI 회귀검사는 실제 UI 핸들러를 최소 DOM·저장소 모형에서 실행합니다. 실제 브라우저 조작·화면 배치 검사와는 다릅니다. 현재 수정본의 모바일 화면, PNG·텍스트 실제 다운로드, 소리 재생, `file://` 실행은 이번에 검증하지 않았습니다. GitHub Pages의 실제 배포 성공도 로컬 검사만으로 보장하지 않습니다.

## 파일 구성

- `dist/`: 수정할 게임 소스와 실행 파일. `life.mjs`는 이야기·선택, `experience.mjs`는 화면·저장·조작을 담당합니다.
- `dist/first-story/`: 기존 첫 버전의 저장을 이어보기 위한 실행 파일.
- `dist/story.mjs`: 첫 버전 이야기의 회귀검사가 사용하는 모듈.
- `docs/`: `dist/`에서 복사한 GitHub Pages 게시용 파일.
- `downloads/stars-we-leave-v0.2.1.zip`: 기존 v0.2.1 다운로드 파일.
- `우리가-남긴-별-v0.2.1.html`: 간편 실행용 단일 HTML.
- `life.test.mjs`, `story.test.mjs`, `ui.test.mjs`: 자동 검사.
- `serve.mjs`, `package.json`: 로컬 서버·명령 설정.
- `verification/assemble-v2.mjs`: 독립 HTML 조립과 구문검사용 모듈 생성.
- `verification/build-pages.mjs`, `verification/verify-pages.mjs`: 게시 파일 준비·검사.
- `변경안내-v0.2.1.txt`: 짧은 변경 안내.

이 저장소에는 별도 라이선스를 지정하지 않았습니다.
